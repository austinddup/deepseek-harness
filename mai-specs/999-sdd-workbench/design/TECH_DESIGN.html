设计原则 整体架构 数据结构 数据流程 模块抽象 变更文件 核心代码 方案小结

rule设计原则

  • 只做 Client 插件。Host 侧无逻辑，不新增接口；读取全部复用 remote.workspaceFiles 的 read 与 list。
  • 只读且不出 mai-specs。read 本身允许读工作区外路径，所以插件只读固定相对路径 mai-specs/ROADMAP.md；Feature 目录先在插件内归一化，必须位于 mai-specs/ 之下，再交给只能列工作区内目录的 list，形成双重保护。
  • 读取总量有上限。ROADMAP 先用 stat 查大小，超过 2 MB、已读文本累计超过 2 MB 或累计超过 2 万行即停止并丢弃已读内容，整页报“文件过大”；每个 Feature 累计最多列 2000 个条目，超出或 Host 返回截断时照常显示已读到的文件并提示列表不完整。插件不修改文件。
  • 纯函数承载规则。解析、越界判断、排序、过滤都不依赖 React 与网络；页面组件只管状态与渲染，读取能力以回调注入，组件不接触 ctx。
  • 遵守仓库通用规则。过滤用仓库统一的 TextSearchIndex（编号、标题模糊匹配，路径子串匹配，多词，按匹配度排序）；文案覆盖 8 种发布语言。
  • 复用现成能力。引导页卡片、文档预览、文件地址函数、UI 基础组件都用已有的；不自绘 Markdown，不新画图标，不加插件配置。

拟议代码 · roadmap.ts · parseRoadmap / compareIds：按表头名定位列，兼容四列与五列；无效行跳过，缺失分区视为空；组内按编号升序，最新 Feature 在最上面；行键不依赖行序号

/** ROADMAP 的三个二级标题，按显示顺序排列。 */
export const SECTIONS = [
  { key: 'in-progress', heading: '进行中' },
  { key: 'planned', heading: '规划中' },
  { key: 'done', heading: '已完成' },
] as const
export type SectionKey = typeof SECTIONS[number]['key']

export type FeatureDir =
  | { readonly kind: 'inside'; readonly path: string } // mai-specs/ 之下的工作区相对路径，如 'mai-specs/999-sdd-workbench'
  | { readonly kind: 'outside' }

export interface RoadmapFeature {
  /** 行键：`${section}:${link}:${同分区同链接的出现序号}`。插入或删除其他行不会改变它。 */
  readonly key: string
  readonly section: SectionKey
  readonly id: string
  readonly title: string
  /** 空单元格为 undefined，界面不显示。 */
  readonly priority: string | undefined
  /** 标题列链接原文，用于“目录缺失”提示中的路径。 */
  readonly link: string
  readonly dir: FeatureDir
}

export type Roadmap = Readonly<Record<SectionKey, readonly RoadmapFeature[]>>

export function parseRoadmap(markdown: string): Roadmap {
  const result: Record<SectionKey, RoadmapFeature[]> = { 'in-progress': [], planned: [], done: [] }
  for (const { key: section, heading } of SECTIONS) {
    const body = sectionBody(markdown, heading)   // 该 `## heading` 到下一个 `## ` 之间的文本；缺失 → undefined
    if (body === undefined) continue               // 缺失分区视为空
    const table = firstTable(body)                 // 第一组连续的 `|` 行：表头、分隔行、数据行；没有 → undefined
    if (table === undefined) continue
    const col = columnIndex(table.header)          // 按表头文字找“需求”“标题”“优先级”的列号
    if (col === undefined) continue                // 缺“需求”或“标题”列 → 无法识别，视为空分区
    const seen = new Map<string, number>()         // 链接原文 → 已出现次数，区分重复行
    for (const cells of table.rows) {
      const row = parseRow(cells, col)
      if (row === undefined) continue              // 无效行跳过
      const n = seen.get(row.link) ?? 0
      seen.set(row.link, n + 1)
      result[section].push({ ...row, section, key: `${section}:${row.link}:${n}` })
    }
    result[section].sort((x, y) => compareIds(x.id, y.id))   // 稳定排序：同编号保持 ROADMAP 行序
  }
  return result
}

/** 纯数字编号按数值升序（倒序分配 → 最新在上），先于非数字编号；非数字编号按码点序（code-point.ts）。 */
export function compareIds(a: string, b: string): number {
  const numericA = /^\d+$/.test(a), numericB = /^\d+$/.test(b)
  if (numericA && numericB) return Number(a) - Number(b)
  if (numericA !== numericB) return numericA ? -1 : 1
  return compareCodePoints(a, b)
}

function parseRow(cells: readonly string[], col: Columns): Omit<RoadmapFeature, 'key' | 'section'> | undefined {
  const id = cells[col.id]?.trim()
  const link = firstMarkdownLink(cells[col.title] ?? '')   // `[text](target)` → { text, target }
  if (!id || link === undefined || !link.text.trim()) return undefined
  const dir = resolveFeatureDir(link.target)
  if (dir === undefined) return undefined                   // URL / 绝对路径 / 锚点 / 无法解码 → 无效行
  const priority = col.priority === undefined ? undefined : cells[col.priority]?.trim() || undefined
  return { id, title: link.text.trim(), priority, link: link.target, dir }
}

拟议代码 · roadmap.ts · resolveFeatureDir：拒绝 URL、绝对路径、锚点；先解码再归一化，父目录不在 mai-specs/ 之下即越界

const SCHEME = /^[a-z][a-z0-9+.-]*:/i

/**
 * @returns undefined：不是可用的相对路径链接（行无效）；outside：不在 mai-specs/ 之下；inside：mai-specs/ 下的工作区相对目录。
 */
export function resolveFeatureDir(target: string): FeatureDir | undefined {
  let t = target.trim()
  if (t.startsWith('<') && t.endsWith('>')) t = t.slice(1, -1)          // CommonMark 尖括号链接 `<a b/BRIEF.md>`
  if (t === '' || t.startsWith('#') || t.startsWith('/') || t.startsWith('\\') || SCHEME.test(t)) return undefined
  const raw = t.split(/[?#]/)[0]                                         // 去掉查询串与锚点
  let decoded: string
  try { decoded = decodeURIComponent(raw) } catch { return undefined }   // `%E4%BD` 等非法编码 → 无效行
  // 以 mai-specs/ 为基准做 POSIX 归一化：处理 '.'、'..'、重复斜杠、反斜杠。
  const file = posixNormalize(`mai-specs/${decoded.replace(/\\/g, '/')}`)
  const parent = file.includes('/') ? file.slice(0, file.lastIndexOf('/')) : ''
  // 前缀判断必须在归一化之后：'..' 开头（工作区外）、'src'（工作区内其他目录）、'mai-specs' 本身都不是 Feature 目录。
  if (!parent.startsWith('mai-specs/')) return { kind: 'outside' }
  return { kind: 'inside', path: parent }
}

拟议代码 · feature-files.ts · listFeatureFiles：根目录缺失或越界记为缺失，其他错误整体记为失败；深度上限防止链接成环

/** 根目录为第 0 层，最多列到第 8 层。防止工作区内符号链接成环。 */
export const MAX_DEPTH = 8

export type FileListing =
  | { readonly kind: 'loading' }
  | { readonly kind: 'ok'; readonly files: readonly string[] }   // 相对 Feature 目录的路径
  | { readonly kind: 'missing' }                                 // 目录缺失
  | { readonly kind: 'failed'; readonly reason: string }         // 目录读取失败

/** 由 client/index.ts 闭包 ctx.remote.workspaceFiles.list 后注入。 */
export type ListDirectory = (path: string, signal: AbortSignal) =>
  Promise<{ ok: true; entries: readonly WorkspaceDirectoryEntry[] } | { ok: false; code: string; message: string }>

export async function listFeatureFiles(list: ListDirectory, dir: string, signal: AbortSignal): Promise<FileListing> {
  const files: string[] = []
  let level: string[] = ['']                                     // 相对 dir 的待列目录
  for (let depth = 0; level.length > 0 && depth <= MAX_DEPTH; depth++) {
    const next: string[] = []
    for (const rel of level) {
      const answer = await list(rel === '' ? dir : `${dir}/${rel}`, signal)
      if (!answer.ok) {
        const rootMissing = rel === '' && (answer.code === 'workspace-file/not-found' || answer.code === 'workspace-file/outside-workspace')
        return rootMissing ? { kind: 'missing' } : { kind: 'failed', reason: answer.message }
      }
      for (const entry of answer.entries) {
        if (entry.name.startsWith('.')) continue                 // 隐藏文件不列出
        const path = rel === '' ? entry.name : `${rel}/${entry.name}`
        if (entry.type === 'directory') next.push(path)
        else files.push(path)                                    // 'file' 与 'other' 都列出，由预览决定能否打开
      }
    }
    level = next
  }
  return { kind: 'ok', files: sortFiles(files) }
}

/** BRIEF.md 置顶，其余按 Unicode 码点序（确定性，不受界面语言影响；与 JS 的 `<` 按 UTF-16 码元比较不同，含表情等字符时结果有别）。 */
export function sortFiles(files: readonly string[]): string[] {
  return [...files].sort((a, b) => a === 'BRIEF.md' ? -1 : b === 'BRIEF.md' ? 1 : compareCodePoints(a, b))   // 逐个码点比较
}

拟议代码 · filter.ts · buildIndex / filterFeatures：每个文件一项并携带所属 Feature 的编号与标题；编号或标题命中显示全部文件，仅文件命中只显示命中文件；组内按匹配度排序

/** 每个 Feature 一项（path 为 undefined），每个已列出的文件一项；文件项也带所属 Feature 的编号和标题，让 `999 prd` 这类多词查询能命中。 */
interface Item { readonly feature: RoadmapFeature; readonly path: string | undefined }

const keys = (item: Item): SearchKeys => ({
  fuzzy: [item.feature.id, item.feature.title],                  // 编号、标题：子串或词首模糊匹配
  substring: item.path === undefined ? [] : [item.path],         // 路径：只按连续子串匹配
})

export type FilesOf = (dir: string) => FileListing | undefined

/** previous：上一次的索引，复用已准备的键（文件清单到达后 useMemo 重建时传入）。 */
export function buildIndex(roadmap: Roadmap, filesOf: FilesOf, previous?: TextSearchIndex<Item>): TextSearchIndex<Item> {
  const items: Item[] = []
  for (const { key } of SECTIONS) {
    for (const feature of roadmap[key]) {
      items.push({ feature, path: undefined })
      const listing = feature.dir.kind === 'inside' ? filesOf(feature.dir.path) : undefined
      if (listing?.kind === 'ok') for (const path of listing.files) items.push({ feature, path })
    }
  }
  return previous === undefined ? new TextSearchIndex(items, keys) : previous.update(items, keys)
}

export interface FilteredFeature {
  readonly feature: RoadmapFeature
  /** undefined：编号或标题命中，展开时显示全部文件；数组：仅文件命中，强制展开且只显示这些。 */
  readonly onlyFiles: readonly string[] | undefined
}

export function filterFeatures(index: TextSearchIndex<Item>, query: string): Readonly<Record<SectionKey, readonly FilteredFeature[]>> | 'all' {
  if (query.trim() === '') return 'all'                          // 空关键词：完整列表与原展开状态
  // Map 的插入顺序 = 首次命中顺序 = 匹配度顺序（同分保持构建顺序，即编号顺序）
  const found = new Map<string, { feature: RoadmapFeature; whole: boolean; files: string[] }>()
  for (const { feature, path } of index.search(query)) {
    let entry = found.get(feature.key)
    if (entry === undefined) { entry = { feature, whole: false, files: [] }; found.set(feature.key, entry) }
    if (path === undefined) entry.whole = true                   // Feature 项命中：显示全部文件
    else entry.files.push(path)
  }
  const out: Record<SectionKey, FilteredFeature[]> = { 'in-progress': [], planned: [], done: [] }
  for (const { feature, whole, files } of found.values()) {
    // 命中文件按文件清单的顺序，不按匹配度
    out[feature.section].push({ feature, onlyFiles: whole ? undefined : sortFiles(files) })
  }
  return out
}

伪代码 · WorkbenchBody.tsx · load：刷新失败时保留旧列表并记录错误

type Load =
  | { readonly kind: 'no-workspace' }
  | { readonly kind: 'loading' }
  | { readonly kind: 'uninitialized' }
  | { readonly kind: 'failed'; readonly reason: string }
  | { readonly kind: 'ready'; readonly roadmap: Roadmap; readonly refreshing: boolean; readonly refreshError: string | undefined }

/** 一次加载或刷新；读取失败时，已有列表保留并附带 refreshError。 */
async function load(prev: Load, read: ReadRoadmap, signal: AbortSignal): Promise<Load> {
  const answer = await read(signal)                              // 分页读到 eof 并拼接；read 为注入的回调
  if (answer.ok) return { kind: 'ready', roadmap: parseRoadmap(answer.text), refreshing: false, refreshError: undefined }
  if (prev.kind === 'ready') return { ...prev, refreshing: false, refreshError: answer.message } // 保留旧列表
  return answer.code === 'workspace-file/not-found' ? { kind: 'uninitialized' } : { kind: 'failed', reason: answer.message }
}

// 组件内（示意）。readRoadmap、listDirectory 来自 inject 回调。
const generation = useRef(0)

const refresh = useCallback(() => {
  const mine = ++generation.current
  controller.current?.abort(); controller.current = new AbortController()
  dispatch({ type: 'start' })                                   // ready → refreshing=true；其他 → loading
  void load(stateRef.current.load, readRoadmap, controller.current.signal).then((next) => {
    if (mine !== generation.current) return                      // 被更新的刷新取代
    dispatch({ type: 'loaded', load: next })
    if (next.kind !== 'ready' || next.refreshError !== undefined) return // 失败：缓存不动
    dispatch({ type: 'clear-cache' })                            // 未展开 Feature 的旧清单一并清除
    for (const dir of expandedDirs(next.roadmap, stateRef.current.expanded)) fetchFiles(dir)
    if (stateRef.current.query.trim() !== '') for (const dir of insideDirs(next.roadmap)) fetchFiles(dir) // })
}, [/* … */])

/** 列一个目录并写缓存；代次已变时丢弃结果。同一目录已有 loading/ok 时不重复请求。 */
const fetchFiles = (dir: string) => {
  const mine = generation.current
  if (stateRef.current.files.has(dir)) return
  dispatch({ type: 'files', dir, listing: { kind: 'loading' } })
  void listFeatureFiles(listDirectory, dir, controller.current!.signal).then((listing) => {
    if (mine !== generation.current) return                      // 被刷新取代或已卸载，不写缓存
    dispatch({ type: 'files', dir, listing })
  })
}

拟议代码 · face.ts · readRoadmap：先查大小再分页，超限即停并丢弃已读页

export const MAX_ROADMAP_LINES = 20_000
export const MAX_ROADMAP_BYTES = 2 * 1024 * 1024
/** 插件自定义的失败码；不是 Host 错误码，state.ts 据此显示 “文件过大”原因。 */
export const ROADMAP_TOO_LARGE = 'sdd-workbench/roadmap-too-large'

const tooLarge = { ok: false, code: ROADMAP_TOO_LARGE, message: '' } as const
const oversized = (bytes: number | undefined) => bytes !== undefined && bytes > MAX_ROADMAP_BYTES
const utf8 = new TextEncoder()

readRoadmap: async (signal) => {
  // 先查大小：Host 报告了 bytes 且超限时，一行内容都不读。
  const stat = await remote.workspaceFiles.stat(sessionId, ROADMAP_PATH, signal)
  if (!stat.ok) return fold(stat)                                   // not-found 等与 read 一致
  if (oversized(stat.value.bytes)) return tooLarge
  const pages: string[] = []
  let total = 0
  let read = 0                                                      // 已读文本的 UTF-8 字节数
  for (let offset = 1; ; ) {
    const page = await remote.workspaceFiles.read(sessionId, ROADMAP_PATH, { offset }, signal)
    if (!page.ok) return page.error.code === 'workspace-file/too-large' ? tooLarge : fold(page)   // 单页超过 Host maxBytes
    if (oversized(page.value.bytes)) return tooLarge                // 文件在两次请求之间变大
    read += utf8.encode(page.value.text).byteLength
    if (oversized(read)) return tooLarge                            // Host 不报告大小时仍守住 2 MB
    total += page.value.lines
    if (total > MAX_ROADMAP_LINES) return tooLarge                  // 已读页随 pages 一起丢弃
    if (page.value.lines > 0) pages.push(page.value.text)
    if (page.value.eof || page.value.lines === 0) return { ok: true, text: pages.join('\n') }
    offset += page.value.lines
  }
}

拟议代码 · feature-files.ts · listFeatureFiles：累计条目上限与 Host 截断都标记不完整；截断只标记，达到上限才停止

/** 每个 Feature 累计最多读入的非隐藏条目数（文件与子目录合计）。 */
export const MAX_ENTRIES = 2000

export type FileListing =
  | { readonly kind: 'loading' }
  | { readonly kind: 'ok'; readonly files: readonly string[]; readonly incomplete: boolean }   // incomplete → “列表不完整”提示
  | { readonly kind: 'missing' }
  | { readonly kind: 'failed'; readonly reason: string }

// ListDirectory 的成功结果增加 truncated（face.ts 原样转交 Host 的值）。
export type ListResult =
  | { readonly ok: true; readonly entries: readonly WorkspaceDirectoryEntry[]; readonly truncated: boolean }
  | { readonly ok: false; readonly code: string; readonly message: string }

export async function listFeatureFiles(list: ListDirectory, dir: string, signal: AbortSignal): Promise<FileListing> {
  const files: string[] = []
  let counted = 0
  let truncated = false                                             // Host 截断了某个目录：只做标记，继续列
  let capped = false                                                // 达到 MAX_ENTRIES：停止一切列目录
  let level = ['']
  for (let depth = 0; level.length > 0 && depth <= MAX_DEPTH && !capped; depth++) {
    const next: string[] = []
    for (const rel of level) {
      const answer = await list(rel === '' ? dir : `${dir}/${rel}`, signal)
      if (!answer.ok) return /* 与 §3 相同：根目录缺失 → missing，其他 → failed（失败优先于不完整） */
      if (answer.truncated) truncated = true
      for (const entry of answer.entries) {
        if (entry.name.startsWith('.')) continue
        if (counted === MAX_ENTRIES) { capped = true; break }       // 第 2001 个：停止
        counted++
        const path = rel === '' ? entry.name : `${rel}/${entry.name}`
        if (entry.type === 'directory') next.push(path)
        else files.push(path)
      }
      if (capped) break                                             // 不再列同层其余目录
    }
    level = next
  }
  return { kind: 'ok', files: sortFiles(files), incomplete: truncated || capped }
}

拟议代码 · state.ts / WorkbenchBody.tsx · 失败原因区分 Host 错误与过大，渲染时按界面语言取文案

/** ROADMAP 读取失败的原因；too-large 在渲染时取 “文件过大”原因，随界面语言切换。 */
export type Reason = { readonly kind: 'host'; readonly message: string } | { readonly kind: 'too-large' }

// Load 中 failed.reason 与 ready.refreshError 由 string 改为 Reason。
export async function load(previous: Load, read: ReadRoadmap, signal: AbortSignal): Promise<Load> {
  const answer = await read(signal)
  if (answer.ok) return { kind: 'ready', roadmap: parseRoadmap(answer.text), refreshing: false, refreshError: undefined }
  const reason: Reason = answer.code === ROADMAP_TOO_LARGE ? { kind: 'too-large' } : { kind: 'host', message: answer.message }
  if (previous.kind === 'ready') return { ...previous, refreshing: false, refreshError: reason }
  return answer.code === 'workspace-file/not-found' ? { kind: 'uninitialized' } : { kind: 'failed', reason }
